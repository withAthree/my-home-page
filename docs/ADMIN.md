# 内容后台使用说明

门户站的所有内容都集中在 `src/data/site.config.ts` 一个文件里（这是 PRD 第 8、9 条的要求：**组件零硬编码文案**）。后台就是给这个文件配的可视化编辑器：改表单 → 校验 → 写回文件，不需要手写 TypeScript。

---

## 一、怎么打开

```bash
npm run admin          # 后台 + 站点预览（会自动拉起 next dev，一条命令搞定）
npm run admin:static   # 已经 npm run build 过，直接用 out/ 静态产物开后台
npm run content:check  # 只做校验，可放进 CI
```

打开终端里打印的地址（默认 <http://127.0.0.1:4600/admin/>）。

`npm run admin` 会先探测 `--target` 端口：已经有站点服务就直接代理，没有就自己 `spawn` 一个 `next dev`；万一起不来（端口冲突、权限问题），预览会自动回退到 `out/` 里的静态产物，后台本身始终可用 —— 后台服务一定是先起来再去做这些事的，不会被站点拖住。

常用参数：

| 参数 | 说明 |
| --- | --- |
| `--port 4600` | 后台端口，被占用会自动 +1 |
| `--target 4000` | `dev` 模式下代理的站点端口 |
| `--git` | 每次保存成功后自动 `git commit`（也可用 `STUDIO_GIT=1`） |
| `--no-open` | 不自动打开浏览器 |

> 后台服务只监听 `127.0.0.1`，且所有接口都要求自定义请求头 `x-studio-request: 1`（跨站表单无法伪造），所以不需要登录，也不要把端口暴露到公网。

## 二、两种工作模式

后台启动时会先探测 `GET /api/studio`：

- **已连接本地服务**（`npm run admin`）：保存会真正写入 `src/data/site.config.ts`，自动备份上一版，支持回滚和 Git 提交。
- **离线草稿**（直接 `npm run dev` 打开 `/admin/`，或部署到线上的 `/admin/`）：保存只写进浏览器的 `localStorage`，页面顶部会显示「离线草稿模式」。改完可以「下载 site.config.ts」覆盖仓库里的文件。

线上（Vercel 等纯静态托管）的 `/admin/` 页面本身是可用的编辑器，但只能是离线模式——静态托管没有写文件的后端，这是刻意的安全设计。

## 三、页面分工

| 分组 | 页面 | 管什么 |
| --- | --- | --- |
| — | 概览 | 站点健康度：错误数、提醒数、各版块条目数、快捷入口 |
| 内容 | 基本信息 | 姓名、英文名、角色标签、状态、标语、介绍段落、关键词、坐标、邮箱、社交链接、头像 |
| 内容 | 技能栈 | 技能分类、熟练度、技能项与说明 |
| 内容 | 项目作品 | 项目卡片：标题、副标题、年份、描述、标签、封面、预览 / 源码链接、置顶 |
| 内容 | 经历时间线 | 年份、标题、组织、描述、标签 |
| 内容 | 摄影集 | 照片路径、标题、地点、年份、分类（分类来自「页面文案 → 摄影集」） |
| 内容 | 导航菜单 | 顶栏菜单项、标签、锚点 |
| 站点 | 页面文案 | 每个版块的小标题 / 大标题 / 描述 / 按钮文字，页脚与版权 |
| 站点 | SEO 与分享 | 站点域名、描述、关键词、分享图、Twitter 卡片类型、是否允许搜索引擎收录 |
| 站点 | 主题配色 | 背景、正文、青、品红、紫、琥珀六个主题色（后台与站点共用同一套 CSS 变量） |
| 工具 | 数据与发布 | 保存、下载源码、改动 diff、备份回滚、Git 提交、危险操作、命令速查 |

几个使用细节：

- 标题类字段支持 `*强调*`（渲染成渐变文字）和换行，输入框下方会实时预览效果。
- 列表条目可以用 ↑ / ↓ 按钮调整顺序，也可以复制、删除（二次确认）。
- 图片字段可以直接从 `public/images/` 里挑，也可以上传新图（会自动落到 `public/images/` 并做重名避让）。
- 工作年限**不用手写**：文案里写占位符，渲染时由代码算 —— `{years}` = 工作年限（当年 − 2021，2026 年就是 `5`）、`{since}` = 参加工作年份、`{year}` = 当年。例：首屏数据条填 `{years}Y+`，2026 年显示 `5Y+`，2027 年自动变 `6Y+`。页脚版权行另外支持 `{name}`。起点年份想改的话只改 `src/data/career.ts` 里的 `CAREER_START_YEAR`。后台「数据与发布」的提醒里，如果哪一处年限被写死了会给你标出来。
- `Ctrl+S` 保存，`Ctrl+Z` 撤销，`Ctrl+Shift+Z` / `Ctrl+Y` 重做（连续打字算一步，最多 60 步）。
- 右上角「实时预览」会在右侧用 iframe 加载 `/?studio=1`，把当前草稿通过 `postMessage` 推给它，**保存前就能看到效果**；可以切换桌面/平板/手机三种宽度。
- 页面地址带 hash（如 `/admin/#projects`），刷新后停在同一页。

## 四、保存到底做了什么

```
表单改动 → validateConfig（有 error 就 422 拒绝）
        → 备份 src/data/site.config.ts 到 .studio/backups/（最多留 40 份）
        → codegen 重新生成对象字面量（保留文件头注释与 interface 定义）
        → 临时文件 + rename 原子写入
        → 可选 git commit
```

- **错误（error）**：必填为空、格式不对、id 重复、条数不足 —— 会阻止保存，并在左侧导航对应的页面上标数字。
- **提醒（warn）**：导航锚点指向不存在的版块、照片分类不在筛选表里、项目全都没填链接、主题背景偏亮、`public/images` 里有没用到的图 —— 只提示，不拦你。
- **备份回滚**：`数据与发布 → 备份与回滚`，点一下就恢复，当前版本会先自动备份，回滚也能反悔。
- **改坏了怎么办**：`git checkout -- src/data/site.config.ts`，或者用 `.studio/backups/` 里的任意一份。

## 五、数据契约

`src/data/site.config.ts` 的结构由 `src/data/schema.ts` 描述，后台表单**完全由 schema 驱动**——加一个字段只需要在 schema 里加一个 `FieldDef`，表单、校验、代码生成、体检提示会一起生效，不用碰 UI 代码。

相关文件：

| 文件 | 职责 |
| --- | --- |
| `src/data/site.config.ts` | 站点内容（唯一数据源） |
| `src/data/schema.ts` | 字段定义、页面分组、通用校验器（浏览器与 Node 共用） |
| `src/data/codegen.ts` | 把 JSON 还原成带注释和类型的 `site.config.ts` |
| `src/data/validate.ts` | 保存前校验 + 内容体检 |
| `src/admin/*` | 后台界面（纯客户端，零新增依赖） |
| `scripts/studio.cjs` | 本地服务：读写文件、备份、上传、Git（Node 内置模块，零依赖） |

## 六、注意事项

- 后台是**编辑器**，不要在编辑过程中手动改同一个文件，否则以最后一次保存为准（保存前会提示差异）。
- 站点是静态导出（`output: "export"`），内容改完记得 `npm run build` 才会更新线上产物。
- 摄影集新增图片时，文件名建议用英文/数字短横线；上传接口会做安全化处理，但可读的文件名更好维护。
- 部署前可以跑 `npm run content:check`，它同时会验证「生成器幂等」——即保存后的文件再读一遍仍然稳定，不会来回抖动。
